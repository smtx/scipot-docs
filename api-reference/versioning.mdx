## Current version

**`0.2.0`** — first deliberately-tracked release. See the [CHANGELOG](https://github.com/smtx/scipot-core/blob/main/CHANGELOG.md) for the full history.

You can read the active version programmatically:

```bash
curl -s https://api.scipot.ai/openapi.json | jq -r .info.version
# → "0.2.0"
```

Every authenticated response also carries an `X-API-Version` header echoing the version that handled the request.

## The promise (and the caveat)

While the API is below `1.0.0`, **minor bumps (`0.x.0`) MAY include breaking changes.** This is the standard SemVer pre-release convention — we use it deliberately because some surfaces are still settling. Every breaking change is:

- Documented in the [CHANGELOG](https://github.com/smtx/scipot-core/blob/main/CHANGELOG.md) under the version that introduces it.
- Announced ≥30 days before removal in the body of `Deprecation` / `Sunset` response headers when applicable.
- Mentioned in our release notes / Twitter / newsletter at the time of the bump.

**Consumers should pin to a known-good minor version** during the 0.x phase. Once the API stabilises we'll cut `1.0.0` and adopt strict SemVer (breaking changes only in major bumps).

## What we mean by "breaking"

| Change | Breaking? | Goes into |
|---|---|---|
| Add a new optional field to a request | No | next 0.x.y (patch) |
| Add a new field to a response | No | next 0.x.y |
| Add a new endpoint | No | next 0.x.y |
| Add a new value to an enum | No | next 0.x.y — your code should ignore unknown values |
| Remove a deprecated field | **Yes** | next 0.x.0 (minor, while < 1.0) |
| Change a field's type | **Yes** | next 0.x.0 |
| Change a field from optional to required | **Yes** | next 0.x.0 |
| Remove an endpoint | **Yes** | next 0.x.0, after a 30+ day deprecation window |
| Remove or rename an enum value | **Yes** | next 0.x.0 |
| Change the meaning of an error code | **Yes** | next 0.x.0 (we'd rather add a new code) |

After we cut `1.0.0`, "Yes" moves to `2.0.0` and strict SemVer applies.

## Headers you'll see

### `X-API-Version`

Echoes the version that handled the request:

```http
X-API-Version: 0.2.0
```

Always present. Log it in your client so you can correlate behaviour changes with releases.

### `Deprecation`

Present when the endpoint or a field you used is deprecated. Value is an RFC 3339 date for when deprecation started:

```http
Deprecation: 2026-05-11T00:00:00Z
```

If you see this header, plan migration before the `Sunset` date.

### `Sunset`

Present alongside `Deprecation`. Date when the endpoint/field will be removed:

```http
Sunset: 2026-08-11T00:00:00Z
```

Standard window: **30 days minimum**, typically 60–90 days for endpoints we believe are in active use.

Surface these in your logs:

```typescript
const res = await fetch(url, opts);
const deprecation = res.headers.get("Deprecation");
const sunset = res.headers.get("Sunset");
if (deprecation) {
  console.warn(`[scipot] DEPRECATED since ${deprecation}, sunset ${sunset} — ${res.url}`);
}
```

## Deprecation lifecycle

1. **Day 0** — replacement ships. Old version continues working unchanged.
2. **Day 0** — `Deprecation` + `Sunset` headers added to responses involving the old version. Entry added to the CHANGELOG under `### Deprecated`.
3. **Day 0 → Sunset** — both old and new work. Migrate at your pace.
4. **Sunset day** — old version removed. Calls return `410 Gone` with `error.code: "VERSION_SUNSET"`.

## What's stable across 0.x — load-bearing surfaces

Even within 0.x, some shapes are load-bearing enough that we won't change them without strong reason:

- **The POT Score scale (0.0–1.0)** and the `CONSTITUTION = 1.0` semantic. Half the value of SciPot lives in this contract.
- **The 6-tier `PotScoreLevel` enum** (`CONSTITUTION` / `VERIFIED` / `SUPPORTED` / `INFERRED` / `HYPOTHESIS` / `SPECULATION`) returned in `level` fields.
- **The five epistemic edge types** (`SUPPORTS`, `CONTRADICTS`, `REFINES`, `DERIVES_FROM`, `IS_PART_OF`).
- **UUIDv7 as the identifier format** for all entities.
- **The error envelope** for `ScipotError`-typed responses: `{error: {code, message, cause, fix, docs_url, request_id, retryable}}`.

If we change one of these, it's a 1.0-tier event.

## Stability tags within 0.x

Not every endpoint is at the same maturity level. Per-endpoint pages may carry a stability tag:

- **`stable`** — production-grade. Backed by the 30-day deprecation window.
- **`beta`** — functionally complete but may evolve in minor breaking ways with explicit per-endpoint notice. Use in production at your own pace.
- **`experimental`** — we're trying out the shape. May change or be removed at any time. We'll try to warn but can't promise the deprecation window.

Today, most endpoints are `stable`. The contradiction-resolution surface (`/edges/{edge_id}/stances`, `/edges/{edge_id}/resolve`) and the lab endpoints are `experimental`.

## Why we're on 0.x

SciPot is shipping fast. The retrieval router, the contradiction resolution flow, the contributor expertise model, and the curation workflow are all surfaces where we expect to learn from real usage and adjust. The `0.x` line gives us that flexibility without lying about stability.

When we cut `1.0.0`, we'll stop accepting breaking changes without a major bump. We expect that to happen once we have ≥5 external integrators relying on the surface in production.

## The CHANGELOG

The [CHANGELOG](https://github.com/smtx/scipot-core/blob/main/CHANGELOG.md) follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) format. Two principles:

- **Every breaking change has an entry.** If you find one without an entry, that's our bug — open an issue.
- **Every entry has a date, a description, and where applicable a before/after example.**
