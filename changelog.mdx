This page is the public record of the API's releases and is updated on every release. The current API version is reported in the `X-API-Version` response header on every authenticated request.

<Note>
**Pre-1.0 versioning.** While the API is below `1.0.0`, minor version bumps (`0.x.0`) MAY include breaking changes. We always document them here, but consumers should pin to a known-good minor version. Once the API stabilises, we'll cut `1.0.0` and adopt strict SemVer (breaking changes only in major bumps). See [Versioning](/api-reference/versioning) for the full policy.
</Note>

## 0.6.0.0 — 2026-09-16

**Breaking in what the response says, not in what it returns.** `/query` and `/synthesize` now report the retrieval that actually ran, and `strategy: "cag"` is refused instead of silently coming back empty.

### Changed

- **BREAKING: `POST /pots/{pot_id}/query` and `/synthesize` run RAG, or GraphRAG for relational questions, and never CAG. `strategy: "cag"` on `/query` answers `501 STRATEGY_NOT_AVAILABLE`.** CAG never returned a fact through these two endpoints: the cache behind their router was never loaded, so every factual question already fell back to RAG and `strategy: "cag"` always returned zero results. The facts you receive do not change. The routing metadata does:

  | `/query` metadata | Before | Now |
  |---|---|---|
  | `strategy: "cag"` | `200`, zero results | `501 STRATEGY_NOT_AVAILABLE` |
  | `strategy_used` for a factual question | `cag_with_rag_fallback` | `rag` |
  | `cag_attempted` | `true` | `false` |
  | `fallback_triggered` / `fallback_reason` | `true` / `cag_no_match` | `false` / `null` |
  | GraphRAG `traversal_metadata.seed_strategy_used` / `seed_fallback_triggered` | `cag` / `true` | `rag` / `false` |
  | `gap_signal.reasons` | could include `retrieval_fallback` | no longer does for factual questions |

  `classification.suggested_strategy` still reports what the classifier suggests and can read `cag`; `strategy_used` is what ran. `cag` and `cag_with_rag_fallback` stay in the response schema, and `enable_fallback` is accepted but has nothing to switch. No deprecation window: the removed behaviour never returned a result. See [Errors](/api-reference/errors#retrieval).

### Fixed

- **`POST /pots/{pot_id}/cag/search` no longer returns facts after they are deleted.** Its cache used to live for the whole life of the API process, so a deleted fact kept coming back until a restart. Every non-Constitution result is now confirmed against storage before it is returned, and the cache rebuilds every 5 minutes. Right after a deletion a search can return fewer than `top_k` results until that rebuild; reads are eventually consistent, so a fact deleted less than about 1 second earlier can still appear.
- **`/cag/search` and `/cag/warm` error bodies no longer carry internal exception text.** A `500` carries a fixed message, and a storage backend that reports itself unavailable answers `503` with `Retry-After`, like the rest of the API.

## 0.5.4.0 — 2026-09-13

**Fact-level PII.** Personal data is masked inside the facts, not in the document: the source stays verbatim and the claim survives without the person. See [Fact-level PII](/guides/pii).

### Added

- **The PII layer runs inside the extraction pipeline**, right after the facts are built and **before** deduplication and persistence, so nothing unmasked reaches the fact store, the vector index or an edge. It scans every string the extraction produced for a fact (`content`, `title`, `scope_reason`, `classification.domain` / `subdomain` / `entity_mentions` / `tags`) plus the document-derived strings pinned to it (`location.source_text`, `section_path`, `sheet_name`). Structured entities are masked flat (`{EMAIL}`, `{ES_DNI}`); contextual ones (`NAME`, `ADDRESS`, `AGE`, `USERNAME`) get a **stable per-workspace pseudonym** (`{NAME:7f3a9c1d2e4b}`), so the same person reads the same across facts and documents and edges keep working. POT Score is untouched: it depends on provenance, not on text.
- **New profile lever `pii`** — `{mode: "anonymize" | "block" | "off", contextual_entities, structured_entities, reversible}` — on `POST /profiles`, `PUT /profiles/{id}`, the version record, the job snapshot and the inline preview profile. `null` follows the deployment default, like `scope_aware` follows its flag. `reversible` is reserved: only `false` is accepted. The `pii_exclusion` lever named in the `0.5.1.0` notes was never added; `pii` is the lever, and sending it is no longer a `422`.
- **Premium entitlement, never a silent downgrade.** Switching the layer on needs the workspace's `features.pii`, granted with the new **`PATCH /integrator/workspaces/{workspace_id}/features`**. Without it: `403 PII_NOT_ENTITLED`, raised when the profile is created or updated and again at enqueue, against the lever the run would effectively apply. A features read that fails is `503 PII_ENTITLEMENT_UNAVAILABLE`, not a pass.
- **A floor that runs with the layer off.** Passwords, PINs, card numbers, CVVs and AWS keys are masked on every ingestion, on the local detector only — no external call, no units billed, no entitlement needed. Operators can disable it; `api.scipot.ai` runs it on.
- **`POST /pii/preview`** — the playground. Up to 50 texts and 20 000 characters, a `pii` lever inline or from a stored profile, and per text: the anonymised output, the masked entities with their offsets **in the original text**, the coverage, and `blocked` in `block` mode. Plus a run summary with the text units it cost. **Nothing is stored and no text is logged.** An unentitled workspace gets the floor and a `notice` saying so instead of a `403`. Limits: `413 PII_PREVIEW_CONTENT_TOO_LARGE`, 60/min per integrator (`RATE_LIMIT_EXCEEDED`, `detail.scope = pii_preview`), 8 concurrent per API process (`429 PII_PREVIEW_CONCURRENCY_LIMIT`, `Retry-After: 2`), all echoed in `limits`.
- **Extraction preview:** `include_unmasked: true` returns `facts[].pii.unmasked_content` next to the masked fact — one extraction, a side-by-side view, never persisted. `pii_applied` summarises the run and `profile_applied.pii` reports the lever.
- **Per-fact `pii` block** on every fact (`applied`, `mode`, entity counts by type, `coverage`, `language` — counts and states, never values), and the same run summary on `JobResult.pii` and on the document's extraction record.
- **Declared coverage.** `full`, `partial` or `none` on every run and every fact, the run taking the weakest value of its parts. Asking a structured-only detector for contextual types, or running contextual detection in a language the detector does not promise (Catalan, today), is `partial` — declared, never silent. An unsupported language degrades coverage; it never fails the job.
- **Metering in text units, not tokens.** 1 unit = 1 000 characters, on operations `pii_anonymization` (ingestion), `pii_anonymization_preview` (extraction preview) and `pii_preview` (playground), each tagged `premium` or `floor`. The local detector costs 0 units.

### Changed

- **A detector that cannot answer fails the run.** `PII_DETECTOR_UNAVAILABLE` (`503` on the previews, a job failure on ingestion) is raised before anything is deduplicated or persisted. The layer never falls back to storing unmasked facts.

### Notes for integrators

- `api.scipot.ai` runs the local detector with the layer off by default and entitlement per workspace, so **nothing changes for an existing integration** beyond the floor. Names and addresses need a deployment configured with a managed detector.
- A "disable PII" toggle must send `{"mode": "off"}`. Sending `null` inherits the deployment default, which is on for some deployments.

## 0.5.3.2 — 2026-09-12

### Security

- **A deployment with real tenants refuses to boot with authentication disabled.** Operator-facing: the API now refuses to start when `AUTH_ENABLED=false` meets any signal that the deployment holds real tenant data. With auth off, workspace isolation rested on the caller's own `X-Workspace-ID` header, so the ownership checks shipped in `0.5.3.1` compared that header against itself. Nothing changes for integrators; `api.scipot.ai` has always run with authentication on.
- **New error code `AUTH_UNAVAILABLE` (503).** Returned when a deployment has authentication on but no store to validate keys against. It carries `Retry-After: 30`. Only an operator can clear it, and it is unreachable on a correctly configured deployment. See [Errors](/api-reference/errors#auth-never-retryable-except-auth-unavailable).

### Fixed

- **The auth error codes on this site were wrong.** [Errors](/api-reference/errors) and [Authentication](/get-started/authentication) listed `AUTH_MISSING_KEY`, `AUTH_INVALID_KEY` and `AUTH_WORKSPACE_MISMATCH`, none of which the API has ever emitted, and showed them in the `error` envelope. The real codes are `MISSING_API_KEY`, `INVALID_API_KEY`, `REVOKED_API_KEY`, `EXPIRED_API_KEY` (401), `MISSING_WORKSPACE_ID` / `INVALID_WORKSPACE_ID` (400) and `WORKSPACE_ACCESS_DENIED` (403), and they arrive as `{"detail": {"code", "message"}}` because they are raised by middleware before a request reaches a route. Both pages now document the codes the API actually sends, and the Errors page names the two shapes that sit outside the `error` envelope. `AUTH_FORBIDDEN` (403) was removed too: it appears nowhere in the API, and the real 403 is `WORKSPACE_ACCESS_DENIED`. If you routed on any of the four old names, nothing matched — check your error handling.

## 0.5.2.0 — 2026-09-11

### Added

- **`POST /pots/{pot_id}/extract/preview`** — run the extraction pipeline on a text synchronously and get the facts it would create, **persisting nothing** (no facts, Document, job, vectors or edges; only the usage event, metered like an ingestion). Takes a stored profile (`profile_id`) or an inline one (`profile`, the `POST /profiles` body, never stored). The response is self-describing: `profile_applied`, `language_applied`, `document_context`, `chunking`, the facts in the `GET /facts/{id}` shape, `extraction_audit`, `errors[]` + `partial`, `usage`, `limits`. Declared in the contract: `dedup_scope` is `batch+constitution` (no dedup against the POT's existing facts), `score_stage` is `initial` and `edges` is `null` (no edge detection in this release), `persisted` is `false`. Limits: 12 288 characters (`413 PREVIEW_CONTENT_TOO_LARGE`), 45 s (`504 PREVIEW_TIMEOUT`), 4 concurrent per API process (`429 PREVIEW_CONCURRENCY_LIMIT`, `Retry-After: 5`), 30 per minute per integrator (`429 RATE_LIMIT_EXCEEDED`, `detail.scope = extraction_preview`). See [Extraction Preview](/guides/extraction-preview).
- **Per-route rate limits.** On top of the integrator's global window, a route can have a window of its own (today only the preview). A `429` names the window that refused in `detail.scope` (`global` or the route) and carries that window's `X-RateLimit-*` headers.
- `X-Contributor-ID` is a declared header on the preview, attributing usage events as on `/ingest`.

### Changed

- **`source.path` and `source.author` are bounded** on `/ingest` and the preview: 2048 and 256 characters, `422` above. The path is copied into every fact's provenance.
- A `X-Contributor-ID` that is not a UUID is dropped with a warning instead of silently un-metering the request's usage events.

## 0.5.1.0 — 2026-09-11

### Added

- **Extraction-profile prompt levers.** A profile now carries three more optional levers: `granularity` (`fine` / `standard` / `coarse`), `additional_instructions` (free text, ≤ 1000 chars) and `business_relevance` (free text, ≤ 500 chars). They ride in the job's snapshot like the `0.5.0.0` levers and shape every chunk's extraction; the base prompt's own rules (output format, language, scope, atomicity) take precedence over the free text. Free text is validated at admission and again by the worker: normalised line endings, stripped, `422` when blank, containing control characters, or containing SciPot's guidance delimiters. The levers apply to the LLM extraction only; the deterministic table extractor is unaffected. `pii_exclusion` is a `422`; the PII layer shipped in `0.5.4.0` under a different name, the `pii` lever. See [the levers](/guides/extraction-profiles#the-levers).
- **Expert-endorsed contributions.** `POST /pots/{pot_id}/facts/contribute` accepts `endorsed: bool`; `true` floors the contributed facts at VERIFIED, for a domain expert directly answering a knowledge gap.
- **Knowledge-gap loop.** `POST /pots/{pot_id}/knowledge-gaps`, `GET /knowledge-gaps`, `GET /knowledge-gaps/{gap_id}`, `POST /knowledge-gaps/{gap_id}/transitions` (`open → routed → ingested → resolved`, with `expected_from` as a compare-and-set guard). `POST /pots/{pot_id}/synthesize` and `/query` return `is_knowledge_gap` and a versioned `gap_signal` (v2: relevance-aware).

### Security

- Workspace ids are canonicalised at the request boundary, so a mixed-case `X-Workspace-ID` can no longer strand a POT under an index variant that listing never returns. A storage error on `get_pot` is a retryable `503`, not a silent `404`.

### Removed

- **`DELETE /pots/vectors/reset`** (store-wide, unscoped) and the hidden **`POST /pots/from-directory`**. Neither had an integrator caller. `GET /pots/{pot_id}/vector-debug`, `POST /pots/{pot_id}/vectors/reindex` and `POST /pots/{pot_id}/propagate` are hidden from the public OpenAPI (still callable by operators).

## 0.5.0.0 — 2026-09-10

**Extraction profiles.** A named, versioned bundle of extraction levers owned by a workspace. Ingestion under a profile records `provenance.profile_id` / `profile_version` on every fact, and the version keeps resolving after the profile is edited or deleted. The release line moves to `0.5` because a public entity was added and the ingestion contract changed.

### Added

- **`POST /profiles`**, **`GET /profiles`** (cursor-paginated), **`GET /profiles/{profile_id}`**, **`PUT /profiles/{profile_id}`** (full replacement; bumps `version`; `409` on a concurrent write), **`DELETE /profiles/{profile_id}`** (removes the head, keeps the versions), **`GET /profiles/{profile_id}/versions/{version}`**.
- **`profile_id` on `POST /pots/{pot_id}/ingest` and `POST /pots/{pot_id}/extract-from-document`.** Unknown or another workspace's: `422 PROFILE_NOT_FOUND` before anything is enqueued. The profile is snapshotted into the job at enqueue time.
- **`provenance.profile_id` / `provenance.profile_version` on `Fact`**, and the same pair on each `extraction_history` entry of a document. Additive fields: strict parsers must tolerate them, as with `context_attachment_ids_used`.
- Levers in this release: `language` (precedence: request > profile > POT default > auto-detect) and `scope_aware` (`true` / `false` overrides the deployment flag; `null` follows it). Unknown levers are `422`.

### Documentation

- **New:** [Extraction Profiles](/guides/extraction-profiles) guide, [Extraction Preview](/guides/extraction-preview) guide (added 2026-09-11 with `0.5.3.1` live), the profile pair on [POT Score & Provenance](/trust-mechanics/pot-score-and-provenance#which-profile-produced-this-fact), profile and preview codes on [Errors](/api-reference/errors#extraction-profiles-and-preview).

## 0.4.12.0 — 2026-09-06

### Changed

- **Job records expire.** 30 days after `created_at` a job record becomes eligible for deletion; once removed, `GET /jobs/{job_id}` returns `404` and `GET /jobs` stops listing it. The sweep is asynchronous with no timing guarantee, so 30 days is a floor on availability, not an exact deletion time. A `404` on an old job means "expired", not "never existed". **Do not treat a job id as a durable foreign key:** persist the terminal `result` / `error` on your side when the job completes. Facts and documents are unaffected.
- A finished job no longer keeps a copy of the ingested content on its record; the scrub happens in the same write that marks the job terminal.
- Jobs that had already finished before this release keep their record and do not expire.

## 0.4.8.0 — 2026-09-05

_Ingestion jobs now tell you what went wrong, chunk by chunk. New optional fields and error codes; nothing existing changes type or disappears._

### Added

- **Partial results on ingestion and re-extraction jobs.** When the model fails on some chunks, the job still completes with the facts from the others and reports what it skipped: `result.partial` is `true`, `result.chunks_failed` counts the failed chunks and `result.errors[]` lists the first 25 as `{chunk_index, code, message, retryable}`. Before, a failed chunk silently became zero facts. Re-extract the document to fill the gaps; deduplication keeps the facts you already have.
- **New job error codes:** `LLM_NOT_CONFIGURED` (no provider key on the deployment), `LLM_AUTH_FAILED` (provider rejected the credentials), `LLM_QUOTA` (provider quota exhausted on SciPot's side; no longer mistaken for a retryable rate limit), `LLM_UNAVAILABLE` (provider unreachable or 5xx, retryable), `LLM_ERROR` (anything else). `error.step` is `extracting_facts` when every chunk failed.

### Changed

- **A job whose every chunk fails now fails** with the dominant chunk code, before any fact, vector or edge is written. It used to complete with `facts_created: 0`. When the document also had tables, their deterministic facts are kept and the job completes as partial.
- Document-wide failures (auth, quota, rate limit, provider down) stop early instead of calling the provider once per chunk.
- Every job error is classified by exception class in every write path. `LLM_INVALID_RESPONSE` is retryable; a deleted or foreign POT is `VALIDATION_ERROR`; storage timeouts and throttling are `INTERNAL_ERROR` with `retryable: true`.
- Error messages on the job record never carry provider bodies: status and request id only.
- **A failed job is billed for the tokens it consumed**, exactly once, on success and on failure.

## 0.4.6.0 — 2026-08-02

_Real retention and erasure. Deleting knowledge now deletes it everywhere: storage, edges, embeddings, and, after a bounded window, backups._

### Changed (breaking)

- **`DELETE /documents/{document_id}` cascades by default** (`cascade=true`). Deleting a document erases the facts, edges and embeddings derived from it. Pass `cascade=false` explicitly to keep the previous metadata-and-file-only behaviour.

### Fixed

- **Cascade deletion left every embedding behind.** Deleted facts stayed semantically searchable. All deletion paths now remove the vectors.
- **`DELETE /pots/{pot_id}/facts/{fact_id}` deletes the fact's embedding.** The embedding goes first, with retries; if the vector store stays unavailable the endpoint returns `502` and leaves the fact intact so a retry erases both.
- Vector deletion is retried three times with backoff. Persistent failures surface in the additive `DeletionResult.vector_cleanup_errors` / `PotDeletionDetail.vectors_delete_failed` fields instead of a log line.
- Deleted document objects in backup storage now expire 30 days after deletion, bounding the post-deletion window to the published retention policy.

## 0.3.0 — 2026-05-24

**M21 — Context Attachments.** Curators can pin typed, non-extractable guidance to a document — an `author_note` (free-text framing) or a `json_schema` (reference for negative-space facts) — that travels into every extraction call against that document. The extraction LLM uses the attachment to interpret the primary document but never produces facts attributable solely to the attachment. Every fact created under an M21+ extraction carries a `context_attachment_ids_used` snapshot for full provenance.

### Added

- **`POST /documents/{document_id}/context-attachments`** — create an inline attachment (JSON body, ≤ 16 KB UTF-8).
- **`POST /documents/{document_id}/context-attachments/upload`** — create from a multipart file upload (≤ 80 KB UTF-8). Returns `413 ATTACHMENT_FILE_TOO_LARGE` on overflow.
- **`GET /documents/{document_id}/context-attachments`** — list attachments for a document, ordered by `created_at`.
- **`DELETE /documents/{document_id}/context-attachments/{attachment_id}`** — delete attachment + storage blob. Past facts keep the id on `context_attachment_ids_used`.
- **`context_attachment_ids` parameter on `POST /pots/{pot_id}/extract-from-document`** — `null` (default) resolves to all attachments on the document; `[]` runs extraction with zero attachments; `[...]` runs against a validated subset.
- **`context_attachment_ids_used` field on `Fact`** — three semantic states: a snapshot list for M21+ extractions, `[]` for M21+ extractions with no attachments, `null` for legacy facts.
- **Hard caps:** 5 attachments per document, 80 KB resolved-set bytes, 25 000 tokens in the assembled prompt section.
- **Error vocabulary:** `ATTACHMENT_CAP_EXCEEDED`, `ATTACHMENT_FILE_TOO_LARGE`, `ATTACHMENT_NOT_UTF8`, `ATTACHMENT_TYPE_INVALID`, `ATTACHMENT_REF_INVALID`, `ATTACHMENT_EMPTY` (sync, on create/extract). Worker-side: `ATTACHMENT_FETCH_FAILED`, `ATTACHMENT_DECODE_FAILED`, `ATTACHMENT_CAP_EXCEEDED_AT_EXTRACT`.

### Documentation

- **New:** [Context Attachments](/trust-mechanics/context-attachments) (concept, iron rule, snapshot semantics).
- **New:** [Extraction with Context Attachments](/guides/extraction-with-context-attachments) (curl + JS + Python walkthrough).

## 0.2.0 — 2026-05-11

First version with deliberate version tracking. Includes the public-API preparation work for the [docs.scipot.ai](https://docs.scipot.ai) launch: route cleanup, structured error envelope rail, OpenAPI enrichment.

### Added

- **`ScipotError` exception class** producing the structured error envelope `{error: {code, message, cause, fix, docs_url, request_id, retryable}}`. Routes can opt in incrementally; legacy `HTTPException(detail=...)` raises continue to produce the `{detail: ...}` shape. See [Errors](/api-reference/errors).
- **`docs_base_url` setting** (default `https://docs.scipot.ai/api-reference/errors`, env-overridable) so local/staging environments produce env-correct `docs_url` fields.
- **OpenAPI descriptions enriched** on the top-5 high-traffic routes — `POST /pots`, `POST /pots/{pot_id}/ingest`, `POST /pots/{pot_id}/synthesize`, `GET /pots/{pot_id}/facts`, `POST /pots/{pot_id}/edges/detect`. Mintlify's auto-import now renders rich per-endpoint pages.
- **`GET /pots/by-slug/{slug}`** — workspace-from-header canonical lookup. Replaces the path-arg form (retained as a hidden legacy alias for admin tooling).
- **`POST /pots/from-directory`** — internal-only alias for the legacy YAML-directory loader. Hidden from public OpenAPI.

### Changed (breaking)

- **`POST /pots/from-json` is now `POST /pots`** as the canonical JSON-body POT creation endpoint. The old `/pots/from-json` path is no longer served. The previous `POST /pots` (YAML directory loader) is now `POST /pots/from-directory` and hidden from the public OpenAPI surface.
- **`GET /pots/by-slug/{workspace_id}/{slug}` → `GET /pots/by-slug/{slug}`**, with workspace inferred from the `X-Workspace-ID` header. Legacy path-arg form remains registered but hidden from OpenAPI (deprecated). New code should use the canonical path.
- **`POST /pots/{pot_id}/ingest` 413 removed.** Oversize `content` returns `422` with a Pydantic validation error (schema enforces a 100 KB inline-text cap). The 100 KB cap is specific to this endpoint — larger documents go through `POST /documents/upload` (default 50 MB).
- **Handler `create_pot_from_json` renamed to `create_pot`** for a clean OpenAPI `operationId`. Internal YAML handler stays as `create_pot_from_directory`.
- **OpenAPI `info.description`** updated: auth header is `X-API-Key` (not `Authorization: Bearer`); creation route is `POST /pots`; added link to [docs.scipot.ai](https://docs.scipot.ai).

### Deprecated

- **`POST /pots/{pot_id}/edges/detect-lab`** removed from the public OpenAPI surface (`include_in_schema=False`). Endpoint still works for internal prompt-tuning use but is no longer part of the public API contract.

### Documentation

- **POT Score ladder cross-linking** across the project's internal docs. The dual model — 5-tier external (CONSTITUTION / VERIFIED / EXTRACTED / INFERRED / PENDING) for concept pages and whitepapers, 6-tier internal (CONSTITUTION / VERIFIED / SUPPORTED / INFERRED / HYPOTHESIS / SPECULATION) returned by the API — is now navigable.
