SciPot uses API key authentication. Every authenticated request needs two headers:

```http
X-API-Key: ik_live_xxxxxxxxxxxxx
X-Workspace-ID: 01971abc-...
```

The key identifies your **integrator** (your application's identity). The workspace ID identifies which of your tenants the request is for. SciPot's authorization model is multi-tenant by design — every fact, POT, document, and edge is scoped to a workspace, and the workspace boundary is enforced at the storage layer.

## Get a free API key in 2 minutes

Self-serve signup is open. You'll receive a verification email, click the link, and get your `ik_live_*` key on screen — shown once, copy it before closing the tab.

<Steps>
  <Step title="Register your email">
    ```bash
    curl -X POST "https://api.scipot.ai/auth/signup" \
      -H "Content-Type: application/json" \
      -d '{
        "email": "you@example.com",
        "name": "Your Name"
      }'
    ```

    Response (`201 Created`):

    ```json
    {
      "integrator_id": "01971abc-..."
    }
    ```

    Within ~30 seconds you'll receive an email titled *"Verify your SciPot account"* with a magic-link button.

    Didn't arrive? Check spam, then:

    ```bash
    curl -X POST "https://api.scipot.ai/auth/resend-verification" \
      -H "Content-Type: application/json" \
      -d '{"email": "you@example.com"}'
    ```
  </Step>

  <Step title="Verify your email">
    The magic link in your inbox hits `GET /auth/verify?token=...`. Clicking it opens a page that shows your API key **once** — copy it now, you cannot recover it later.

    If you'd rather verify from the terminal (useful for CI / automation):

    ```bash
    # Replace TOKEN with the token from the email's magic link
    curl "https://api.scipot.ai/auth/verify?token=TOKEN"
    ```

    Response (`200 OK`):

    ```json
    {
      "api_key": "ik_live_xxxxxxxxxxxxx",
      "integrator_id": "01971abc-...",
      "workspace_id": "01971def-..."
    }
    ```

    The response includes both the API key AND a default workspace. SciPot provisions a starter workspace for every new integrator so you can hit the API immediately without a separate setup call.
  </Step>

  <Step title="Use it">
    Export the values and make your first authenticated call:

    ```bash
    export SCIPOT_KEY="ik_live_xxxxxxxxxxxxx"
    export SCIPOT_WORKSPACE="01971def-..."

    curl "https://api.scipot.ai/integrator/workspaces/$SCIPOT_WORKSPACE" \
      -H "X-API-Key: $SCIPOT_KEY"
    ```

    Returns your workspace with its current quotas and usage:

    ```json
    {
      "id": "01971def-...",
      "name": "Default Workspace",
      "slug": "default",
      "is_active": true,
      "quotas": {
        "max_pots": 5,
        "max_documents_per_pot": 50,
        "max_storage_bytes": 52428800
      },
      "usage": { "pots_count": 0, "documents_count": 0, "storage_bytes": 0 }
    }
    ```

    From here go to the [Quickstart](/get-started/quickstart) to build a Company Brain end-to-end.
  </Step>
</Steps>

## What the free tier includes

The default workspace ships with quotas calibrated for evaluation and small projects. You can hit the API immediately without billing setup; if you outgrow the free quotas, upgrade through Stripe via `POST /integrator/billing/checkout` (no contracts, no sales calls).

| Quota | Default |
|---|---|
| POTs per workspace | 5 |
| Documents per POT | 50 |
| Storage per workspace | 50 MB cumulative |
| Token quota | Free tier monthly allowance (raise via top-up or plan upgrade) |

When a quota is hit, the API returns `429 Too Many Requests` with a structured `code` (e.g., `QUOTA_POTS_EXCEEDED`, `QUOTA_STORAGE_EXCEEDED`, `QUOTA_TOKENS_EXCEEDED`). See [Errors](/api-reference/errors).

## Multiple workspaces

Each integrator can manage multiple workspaces — one per tenant if you're building a B2B SaaS, one per environment (dev / staging / prod) for personal use, or one per project for an internal Company Brain split across teams.

```bash
# List your workspaces
curl "https://api.scipot.ai/integrator/workspaces" \
  -H "X-API-Key: $SCIPOT_KEY"

# Create another workspace
curl -X POST "https://api.scipot.ai/integrator/workspaces" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Acme Corp", "slug": "acme"}'
```

A workspace is a **hard data boundary**. Facts, POTs, documents, jobs, and edges from one workspace are never visible from another — even with the same integrator key.

## Request anatomy

A complete authenticated request:

```http
POST /pots/01971abc-.../synthesize HTTP/1.1
Host: api.scipot.ai
X-API-Key: ik_live_xxxxxxxxxxxxx
X-Workspace-ID: 01971abc-...
Content-Type: application/json

{
  "query": "What is our enterprise pricing floor?"
}
```

| Header | Required | Description |
|---|---|---|
| `X-API-Key` | Yes | Your integrator key. Identifies your application. |
| `X-Workspace-ID` | Yes (for any workspace-scoped operation) | The workspace this request operates on. |
| `X-Request-Id` | No | Client-supplied request ID for tracing. If unset, the server generates one and returns it in the response. Log it. |

## Errors

Authentication errors follow the standard [error envelope](/api-reference/errors):

| Code | Cause | Fix |
|---|---|---|
| `401 AUTH_MISSING_KEY` | No `X-API-Key` header. | Add the header. Don't retry. |
| `401 AUTH_INVALID_KEY` | Key not recognized or revoked. | Check the key. If it should be valid, the integrator may have rotated it via the dashboard. |
| `401 AUTH_WORKSPACE_MISMATCH` | The workspace ID doesn't belong to this integrator. | Check `X-Workspace-ID`. |
| `403 AUTH_FORBIDDEN` | Valid key, but lacking permission for this operation. | Some operations (Curator actions, bootstrap) require elevated roles. |
| `429 RATE_LIMITED` | Per-integrator rate cap hit. | Honor `Retry-After`. |
| `429 QUOTA_*` | Workspace quota exhausted. | Upgrade plan or wait for reset. |

Auth errors are never retryable — fix the credentials, don't loop.

## Rate limits

Default integrator limits:

- **60 requests/minute** for read operations.
- **20 requests/minute** for write operations.
- **10 concurrent ingestion jobs per workspace.**
- **LLM-backed operations** (`/synthesize`, `/edges/detect`, `/extract-*`) are subject to your token quota in addition to request-rate limits.

When a limit is hit, the response is `429` with a `Retry-After` header (seconds). Honor it with exponential backoff; do not retry tight loops. Higher limits available on request — these defaults are starting points, not ceilings.

## Rotation and revocation

### Generate a new key

```bash
curl -X POST "https://api.scipot.ai/integrators/$INTEGRATOR_ID/api-keys" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "ci-deploy-key"}'
```

Response includes the new key value **once**. Save it; the server doesn't store it in plaintext.

### Revoke a key

```bash
curl -X DELETE "https://api.scipot.ai/integrators/$INTEGRATOR_ID/api-keys/$KEY_ID" \
  -H "X-API-Key: $SCIPOT_KEY"
```

If a key leaks, revoke it. Revocation propagates within seconds.

## Billing & upgrading (when you outgrow the free tier)

SciPot uses Stripe for self-serve billing. From the same integrator key you can:

```bash
# Open a Stripe Checkout to upgrade your plan
curl -X POST "https://api.scipot.ai/integrator/billing/checkout" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"plan": "pro"}'

# Open the Stripe Customer Portal (manage cards, invoices, downgrade)
curl -X POST "https://api.scipot.ai/integrator/billing/portal" \
  -H "X-API-Key: $SCIPOT_KEY"

# Buy additional token quota without a plan change
curl -X POST "https://api.scipot.ai/integrator/billing/token-topup" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"amount_usd": 10}'
```

Each call returns a Stripe-hosted URL. Redirect the user there; SciPot listens to `POST /billing/webhook` for subscription state changes.

## Security posture

A few things we do and don't:

- **We log every authenticated request** with `request_id`, integrator ID, workspace ID, route, latency, and outcome. We do **not** log request bodies or response bodies in default settings.
- **Keys are stored hashed** (SHA-256). We can't recover a lost key — generate a new one and revoke the old.
- **CORS is allow-listed** per integrator. Add your origins via the dashboard if you're calling from a browser.
- **We don't use your data to train models.** Your ingested documents and extracted facts are scoped to your workspace and only retrieved by your authenticated requests.
- **Email verification is mandatory** for self-serve signup. An unverified account can't use the API.
