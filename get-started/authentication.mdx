SciPot uses API key authentication. Every authenticated request needs two headers:

```http
X-API-Key: ik_live_xxxxxxxxxxxxx
X-Workspace-ID: 01971abc-...
```

The key identifies your **integrator** (your application's identity). The workspace ID identifies which of your tenants the request is for. SciPot's authorization model is multi-tenant by design — every fact, POT, document, and edge is scoped to a workspace, and the workspace boundary is enforced at the storage layer.

## Start a 14-day trial in 2 minutes

Self-serve signup is open and needs no card. You'll receive a verification email, click the link, and get your `ik_live_*` key on screen — shown once, copy it before closing the tab.

<Steps>
  <Step title="Register your email">
    ```bash
    curl -X POST "https://api.scipot.ai/auth/signup" \
      -H "Content-Type: application/json" \
      -d '{
        "email": "you@example.com",
        "name": "Your Name"
      }'
    ```

    Response (`201 Created`):

    ```json
    {
      "integrator_id": "01971abc-..."
    }
    ```

    Within ~30 seconds you'll receive an email titled *"Verify your SciPot account"* with a magic-link button.

    Didn't arrive? Check spam, then:

    ```bash
    curl -X POST "https://api.scipot.ai/auth/resend-verification" \
      -H "Content-Type: application/json" \
      -d '{"email": "you@example.com"}'
    ```
  </Step>

  <Step title="Verify your email">
    The magic link in your inbox hits `GET /auth/verify?token=...`. Clicking it opens a page that shows your API key **once** — copy it now, you cannot recover it later.

    If you'd rather verify from the terminal (useful for CI / automation):

    ```bash
    # Replace TOKEN with the token from the email's magic link
    curl "https://api.scipot.ai/auth/verify?token=TOKEN"
    ```

    Response (`200 OK`):

    ```json
    {
      "api_key": "ik_live_xxxxxxxxxxxxx",
      "integrator_id": "01971abc-...",
      "workspace_id": "01971def-..."
    }
    ```

    The response includes both the API key AND a default workspace. SciPot provisions a starter workspace for every new integrator so you can hit the API immediately without a separate setup call.
  </Step>

  <Step title="Use it">
    Export the values and make your first authenticated call:

    ```bash
    export SCIPOT_KEY="ik_live_xxxxxxxxxxxxx"
    export SCIPOT_WORKSPACE="01971def-..."

    curl "https://api.scipot.ai/integrator/workspaces/$SCIPOT_WORKSPACE" \
      -H "X-API-Key: $SCIPOT_KEY"
    ```

    Returns your workspace with its current quotas and usage:

    ```json
    {
      "id": "01971def-...",
      "name": "Default Workspace",
      "slug": "default",
      "is_active": true,
      "quotas": {
        "max_pots": 3,
        "max_documents_per_pot": 9999,
        "max_storage_bytes": 104857600
      },
      "usage": { "pots_count": 0, "documents_count": 0, "storage_bytes": 0 }
    }
    ```

    From here go to the [Quickstart](/get-started/quickstart) to build a Company Brain end-to-end.
  </Step>
</Steps>

## What the trial includes

The trial lasts **14 days from the moment your email is verified** and needs no card. It is sized to build and test a real integration, not to run one in production. Upgrade through Stripe via `POST /integrator/billing/checkout` at any point (no contracts, no sales calls).

| | Trial |
|---|---|
| Duration | 14 days from email verification |
| Tokens | 10M for the whole trial |
| Workspaces | 1 |
| POTs | 3 |
| Storage | 100 MB cumulative |
| Rate limit | 60 requests/minute |
| Token top-ups | Not available: upgrade to a paid plan for more |
| Fact-level PII | Not available |

The limits are your plan's, and your own key cannot raise them: raising a workspace's quota above the plan (`PATCH /integrator/workspaces/{id}/quotas`), adding tokens to it yourself (`POST /integrator/workspaces/{id}/token-topup`) or switching a premium feature on (PII) answers `403`. Upgrading to a paid plan raises them.

Storage is counted per workspace, and every plan sets its own:

| | Trial | Startup | Growth | Scale |
|---|---|---|---|---|
| Storage per workspace | 100 MB | 1 GB | 5 GB | 20 GB |

A plan change resizes every workspace you already have, up or down. Moving to a plan with less storage deletes nothing: new ingestion answers `429 QUOTA_STORAGE_EXCEEDED` until the workspace fits again.

When a limit is hit, the API answers `429 Too Many Requests` with a structured `code`: `QUOTA_POTS_EXCEEDED`, `QUOTA_STORAGE_EXCEEDED` or `TOKEN_QUOTA_EXCEEDED`. Creating a workspace beyond your plan answers `403 WORKSPACE_LIMIT_REACHED`. See [Errors](/api-reference/errors).

**When the trial ends**, every request other than a `GET` or a `DELETE` returns `402` with code `TRIAL_EXPIRED`, retrieval included. `GET` endpoints keep working so you can export your facts and documents, `DELETE` so you can remove them, and the billing endpoints so you can upgrade with the same key. Your data is kept for 30 days after the trial ends; upgrade within that window and everything is where you left it.

## Multiple workspaces

Each integrator can manage multiple workspaces — one per tenant if you're building a B2B SaaS, one per environment (dev / staging / prod) for personal use, or one per project for an internal Company Brain split across teams. The trial has 1 workspace and paid plans have no workspace limit; creating one beyond your plan answers `403 WORKSPACE_LIMIT_REACHED` (delete a workspace or upgrade).

```bash
# List your workspaces
curl "https://api.scipot.ai/integrator/workspaces" \
  -H "X-API-Key: $SCIPOT_KEY"

# Create another workspace
curl -X POST "https://api.scipot.ai/integrator/workspaces" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"name": "Acme Corp", "slug": "acme"}'
```

A workspace is a **hard data boundary**. Facts, POTs, documents, jobs, and edges from one workspace are never visible from another — even with the same integrator key.

## Request anatomy

A complete authenticated request:

```http
POST /pots/01971abc-.../synthesize HTTP/1.1
Host: api.scipot.ai
X-API-Key: ik_live_xxxxxxxxxxxxx
X-Workspace-ID: 01971abc-...
Content-Type: application/json

{
  "query": "What is our enterprise pricing floor?"
}
```

| Header | Required | Description |
|---|---|---|
| `X-API-Key` | Yes | Your integrator key. Identifies your application. |
| `X-Workspace-ID` | Yes (for any workspace-scoped operation) | The workspace this request operates on. |
| `X-Request-Id` | No | Client-supplied request ID for tracing. If unset, the server generates one and returns it in the response. Log it. |

## Errors

Authentication errors follow the standard [error envelope](/api-reference/errors):

| Code | Cause | Fix |
|---|---|---|
| `401 MISSING_API_KEY` | No `X-API-Key` header. | Add the header. Don't retry. |
| `401 INVALID_API_KEY` | Key not recognized. | Check the key. If it should be valid, the integrator may have rotated it. |
| `401 REVOKED_API_KEY` | The key was revoked. | Issue a new key. |
| `401 EXPIRED_API_KEY` | The key passed its expiry date. | Issue a new key. |
| `400 MISSING_WORKSPACE_ID` | No `X-Workspace-ID` header. | Add the header. |
| `400 INVALID_WORKSPACE_ID` | `X-Workspace-ID` is not a valid UUID. | Send the workspace UUID as issued. |
| `403 WORKSPACE_ACCESS_DENIED` | The workspace doesn't belong to this integrator. | Check `X-Workspace-ID`. |
| `503 AUTH_UNAVAILABLE` | The deployment has auth on but no integrator store. Nothing you send fixes it. | Retry after `Retry-After` (30s); if it persists, it is on the operator. |

These arrive as `{"detail": {"code", "message"}}`, not the `error` envelope the
[Errors](/api-reference/errors) page describes — they are raised by middleware,
before the request reaches a route.
| `429 RATE_LIMITED` | Per-integrator rate cap hit. | Honor `Retry-After`. |
| `429 QUOTA_*` | Workspace quota exhausted. | Upgrade plan or wait for reset. |

Auth errors are never retryable — fix the credentials, don't loop.

## Rate limits

Default integrator limits:

- **60 requests/minute** for read operations.
- **20 requests/minute** for write operations.
- **10 concurrent ingestion jobs per workspace.**
- **LLM-backed operations** (`/synthesize`, `/edges/detect`, `/extract-*`) are subject to your token quota in addition to request-rate limits.

When a limit is hit, the response is `429` with a `Retry-After` header (seconds). Honor it with exponential backoff; do not retry tight loops. Higher limits available on request — these defaults are starting points, not ceilings.

## Rotation and revocation

<Warning>
**Self-service key rotation and revocation is not available yet.** The `/integrators/{id}/api-keys` endpoints exist, but they are operator endpoints: they take the deployment's bootstrap key, not your `ik_live_` key, which they refuse with `401`. An integrator-side `/integrator/api-keys` (list and revoke your own keys) is planned; this page will be updated when it ships.
</Warning>

Until then, to rotate or revoke a key, contact SciPot support with your integrator id and the key prefix (`ik_live_` plus the next four characters — never the full key). We issue the new key and revoke the old one; revocation takes effect within seconds.

A new key is shown **once**. Save it; the server doesn't store it in plaintext. If a key leaks, ask for its revocation immediately.

## Billing & upgrading (during or after the trial)

SciPot uses Stripe for self-serve billing. From the same integrator key you can:

```bash
# Open a Stripe Checkout to upgrade your plan: startup, growth or scale
curl -X POST "https://api.scipot.ai/integrator/billing/checkout" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"plan": "startup", "success_url": "https://example.com/ok", "cancel_url": "https://example.com/cancel"}'

# Open the Stripe Customer Portal (manage cards, invoices, downgrade)
curl -X POST "https://api.scipot.ai/integrator/billing/portal" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"return_url": "https://example.com/account"}'

# Buy additional tokens without a plan change (paid plans only; at least 100,000)
curl -X POST "https://api.scipot.ai/integrator/billing/token-topup" \
  -H "X-API-Key: $SCIPOT_KEY" \
  -H "Content-Type: application/json" \
  -d '{"token_amount": 1000000, "success_url": "https://example.com/ok", "cancel_url": "https://example.com/cancel"}'
```

Each call returns a Stripe-hosted URL. Redirect the user there; SciPot listens to `POST /billing/webhook` for subscription state changes.

## Security posture

A few things we do and don't:

- **We log every authenticated request** with `request_id`, integrator ID, workspace ID, route, latency, and outcome. We do **not** log request bodies or response bodies in default settings.
- **Keys are stored hashed** (SHA-256). We can't recover a lost key — generate a new one and revoke the old.
- **CORS is allow-listed** per integrator. Add your origins via the dashboard if you're calling from a browser.
- **We don't use your data to train models.** Your ingested documents and extracted facts are scoped to your workspace and only retrieved by your authenticated requests.
- **Email verification is mandatory** for self-serve signup. An unverified account can't use the API.
